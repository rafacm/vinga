### Added

- **A `tool` span now says which call it ran and which round asked for it** (#533). The `tool_call` event gains `invocation`, the server-minted id of the generation round that asked for the call, and `position`, the call's zero-based place in the list of calls that round returned, moves included. The `tool` span carries them as `vinga.llm.invocation.id`, the same key the round's `llm` span carries its id under, so a call joins its round on one attribute, and as `vinga.tool.call.position`. Together they name exactly one call: with `export_llm_input` on, the span at position n is the n-th `tool_call` part of its round's exported output, so two calls to the same tool in one turn can now be told apart. The provider's own call id is still not on the span or the event: it is far-side bytes, a value shaped like a credential would pass any syntax check, and an adapter mints the same `call_0` for every round where a server sends none. It stays where it was, inside the opt-in LLM input export.
- **A turn now carries a fingerprint of the prompt it was answered with** (#533). The `prompt_assembled` event gains `sha256`, the SHA-256 in lowercase hex of the agent's know-how half (persona, fragments and MCP guidance, server-shipped blocks included) in its canonical rendering, the bytes the half contributes whenever another block follows it. A persona standing alone is sent untrimmed when nothing follows it, and its leading whitespace is not part of the fingerprint, so `"   Be brief."` and `"Be brief."` carry the same value. Every turn span that agent speaks carries it as `vinga.prompt.sha256` beside `vinga.prompt.characters`. Two sessions on the same prompt carry the same value, and an edit that keeps the prompt's length, which the sizes alone cannot see, changes it. It needs no switch and no key: it is a digest of operator configuration, and none of the prompt's text leaves. One residual risk is stated rather than engineered away: a digest confirms a guess only when every other byte of the prompt is known, so a persona copied from a known template with one personal detail filled in could be guessed detail by detail. Keep personal facts in memory, which is never digested, rather than in the persona.
- The `heard` event's `language_confidence` now says which engines fill it (#533): faster-whisper, when it detected the language rather than being pinned by a configured language or the session's earlier detection, and never the OpenAI-compatible transcription provider, so an alert on `vinga.asr.language_confidence` never fires there. Documentation only.

### Changed

- **A generation's time to first spoken token is now the `vinga.llm.first_token_ms` attribute of its `llm` span, and the `first_token` span event is gone** (#533). This is a breaking change to the exported trace schema, made without a deprecation period: a query, alert or dashboard over the `first_token` span event stops matching. Read `vinga.llm.first_token_ms` on the `llm` span instead; where an instant is wanted, it is the span's start plus that many milliseconds. The reason is the backend: Langfuse ingests no span events at all, so the one latency a person feels never reached it, and a fact on a trace now has one carrier, a span attribute, that every backend reads. A recap carries the attribute as a reply round does, and a round that only asked for a tool carries none rather than a zero. The `llm_round` and `llm_recap` events are unchanged.
