### Changed

- **Observing a deployment, and the server's conversation behavior, have task guides of their own, and the server README is the package's own page** (#609). The README's remaining sections move: Listening and barge-in to `docs/run/turn-taking.md`; Masking reply latency and When a reply fails to `docs/run/slow-and-failed-replies.md`; Logging, Watching a deployment as it runs and Exporting traces to `docs/run/logs-and-traces.md`; Capturing a session to `docs/run/capturing-a-session.md`; What a conversation cost to `docs/run/conversation-cost.md`; The conversation store to `docs/run/conversation-store.md`; a model writing a tool call into its speech to Flow 2 of `docs/system-overview.md`; and Stack, Development and the local and smoke lanes to `docs/contributing.md`, in the Develop door. The task-guide index gains an Observing group. The server README now says what the package is, its two endpoints, the four pipeline stages and what it exposes, and points at the task guides and the contributing page; it moves from the Run door to the Develop door, and the `#running-in-a-container` heading stays as a pointer. The generated event reference links the logs guide, and the `record.events.name` column comment names the generated event reference instead of the README's table, through a comment-only migration (`1011_events_cite_the_reference`) that changes nothing else. Three commands no longer put a secret where the shell or the process table can show it: the Langfuse model definition names a curl configuration file only its owner can read (`curl -K ~/.langfuse-curlrc ...`), the direct Langfuse OTLP header is built into an environment file through a pipe, and the smoke lane hands its throwaway secrets to `docker run` by name. The smoke lane also uses a database of its own, `vinga_smoke`, where it used to seed over the development configuration. The filler and fallback examples now edit the exported `agent_defaults` entry and apply it, since `vinga-server config agent-defaults set` replaces the whole entry. Statements the moved text made that were wrong against the code are corrected, among them: content attached to an unsampled turn is reported as exported, not `no_trace`; `export_llm_input` also exports tool arguments and results, recap requests and remembered facts, and exported text outlives local erasure; the capture manifest keeps each provider's name, type, host and model rather than its resolved entry, a capture also keeps per-turn clips, the 2000 MB budget is about six hours, and `export_audio` uploads recordings off the host; a resumed conversation carries its tool calls' arguments and results; a deleted thread takes its memory with it; `vinga metric`, `vinga session` and `vinga conversation` read the record; only fallback synthesis is bounded; and the server holds a Langfuse key pair when it exports directly or uploads recordings, and never uses it to write a model definition.
