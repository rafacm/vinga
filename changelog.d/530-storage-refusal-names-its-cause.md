### Fixed

- **A database migration that fails for a reason other than the connection no longer says the database cannot be opened** (#530). A boot or a CLI command whose migration failed used to answer every cause it did not recognize with `cannot open the vinga database`, the sentence telling an operator to check the instance's host, port, database name and credentials, even when the instance was up and accepting them throughout. That sentence is now said only when the connection could not be made or was lost (a refused port, a host name that does not resolve, a database, role or password the instance does not have or accept, a connect timeout). A database stamped at a migration this install does not carry gets a sentence of its own that names the revision, says the fault is in the install (a newer build migrated the database, or this install is stale or partial and is missing a migration), and says not to drop or reset the database; the revision is named only when it has the shape of one this project writes, since it is read from the database. Any other failure now says `the vinga database could not be brought up to the schema this server runs on (<ClassName>)`, naming the exception's class and nothing else, which is what the configuration store's own storage refusal already said. As before, no refusal repeats a driver's message, a connection string, a statement or its bound values. The memory and conversation-erasure API responses are unchanged.
