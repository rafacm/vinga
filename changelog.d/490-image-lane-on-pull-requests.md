### Changed

- **Image-affecting pull requests build and smoke the image again** (#490). The image lane had carried an exemption from pull requests since a busy release period, when four builds, arm64 under QEMU and a whole smoke conversation were the longest pole in every round-trip, and the exemption meant a change that broke the image said so only after the merge, or only when somebody remembered to dispatch the workflow by hand. What makes running it affordable again is the split this issue already made: a pull request builds each architecture into the runner's own daemon and smokes that, and pushes nothing at all. It therefore needs no registry credential, which is what lets a pull request from a fork run the lane with the read-only token it has, and it leaves no untagged version behind in the package. The publish job still runs on a push and a dispatch only, since a pull request produces no digests to assemble, and `workflow_dispatch` remains the one pre-merge event that exercises the publishing half end to end.
