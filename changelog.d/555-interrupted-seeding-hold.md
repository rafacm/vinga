### Fixed

- **The interrupted-seeding integration case no longer fails when the test run is started in the background, and now interrupts a write rather than a start-up** (#555). A test runner started as an asynchronous list (`uv run pytest ... &`) inherits SIGINT ignored, a shell cannot trap a signal ignored on entry, and so the seeding script's interrupt handler never ran: the signal was dropped and the seeding finished with status zero, which read as a failure under load and was the launch instead. The case now launches the script with SIGINT ignored, so every run meets that condition, and resets it to the default in a launch step of its own before the script starts. It also holds the script at its second write with a stand-in `vinga-server` on its `PATH` before interrupting, so it asserts that the write in progress finished and no later one began. Previously the signal landed while the script was still starting its server, in every run measured. The seeding scripts are unchanged.
