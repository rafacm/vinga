### Added

- **`vinga device invite` issues the link that joins a browser** (#612). It prints one single-use invite link on stdout and nothing else there, so `$(vinga device invite)` holds a link without showing it, and says on stderr that it worked. Each `--agent <name>`, repeatable, names an agent the browser that opens the link is bound to; with none, it is bound to the default agent. Issuance refuses, issuing nothing, when a named agent is not one the deployment has or not one the server is serving, and neither refusal quotes the name. The agents ride with the link's token in the server's memory, and the redemption binds exactly those, resolving them again inside its one transaction, so an agent deleted in between binds nothing. A link still works once, for ten minutes, ends with a restart, carries its token in the fragment and is redeemed only by the page's own origin; at most 32 wait at once, and a browser it binds is still named `Browser <mac>`.

### Changed

- **The try link is the invite link, and the browser page moved to `/talk/`** (#612). `vinga info` reports and no longer issues a link or prints the line it stood on. `POST /api/runtime/try-links` is `POST /api/runtime/invites`, with a required body whose optional `agents` list names the browser's agents (`{}` names none); an unknown agent is a 422 with the `agents-unknown` reason and an unserved one a 409 with `agent-not-serving`. The page, its modules and its redemption are served under `/talk/` (`/talk/static/...`, `POST /talk/redeem`), a browser with no identity asks for one at `/x/<key>/browser-identity`, and `server.ota_path` reserves `/talk/` instead of `/try/`. The old paths are not aliased: each answers the stock 404. The page no longer says a redeemed browser is bound to the default agent, since the link may have named others.

  Upgrade: the browser page is at `/talk/` now, and `/try/` shows nothing, so open `/talk/` instead; a browser that already joined keeps its identity and is still the same device there. `vinga info` no longer prints a link: run `vinga device invite` for one, and anything that called `POST /api/runtime/try-links` calls `POST /api/runtime/invites` with a body, `{}` for the default agent.
