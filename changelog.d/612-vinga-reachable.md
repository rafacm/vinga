### Changed

- **Every bound device also reaches vinga, the built-in agent** (#612). While the server serves vinga, a device with any binding reaches it beside the agents it is bound to: after them, unless its binding already names vinga, in which case it stays where it was put. A conversation opens on the first reachable agent: the first bound agent the server serves, or vinga when none of them is served yet. Asking the agent that answers for vinga is a handover, so `switch_agent`, offered wherever a device reaches more than one served agent, now appears on a device bound to a single served agent too, naming that agent and vinga; a device that reaches vinga alone is not offered it. Nothing is written into the bindings and vinga carries no MCP tool, so no device gains a grant. A device with no binding still reaches nothing, and while an agent stored under the name vinga displaces the built-in, that agent is reached only by the devices bound to it. A device bound only to agents the running world does not serve yet now talks to vinga while it waits, rather than being refused a token.

  Upgrade: nothing to run. An agent on a device bound to it alone is now offered `switch_agent`, one more tool in its list; on a small local model, check that its tool calls still land (the local lane's `tests/local/test_tool_calling_for_real.py` does this, and Gemma 4 e4b called the right tool in each of ten runs with it and ten without). On a Raspberry Pi the first round's prompt, about two thousand tokens, can take longer to read than `llm_first_token_timeout_s` allows when the runner's prompt cache is cold, with or without the extra tool.
