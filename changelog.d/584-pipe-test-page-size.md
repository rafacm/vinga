### Fixed

- **The test that runs `vinga-server events reference` into a nearly full pipe now builds that pipe in whole pages** (#584). It pre-filled the pipe to leave free the document's length rounded down to 8,192-byte chunks, which holds only where that comes to whole pages, because a Linux pipe is made of pages and a large write is not merged into a half-filled last one. On a kernel with 16 KiB pages it failed deterministically, half a page short of full, and it would have passed or failed as the event catalog grew. The free space is now the most whole pages the document overfills, read from the machine's page size, and a new assertion refuses a construction whose leftover would not fit the child's stdout buffer, which is the regime where the test passes whether or not the command flushes inside its broken-pipe boundary. By the same arithmetic, the old construction had been in that regime on 4 KiB-page machines for the current catalog.
