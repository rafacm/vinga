### Changed

- **Five refusals now say which state they are in, and the CLI says what to run about it** (#488). A refusal composed by the server used to end by naming a command of the CLI's grammar: `vinga-server config device pending list` for an activation code nothing is waiting under, `vinga-server config list` for a claim naming an agent that does not exist, `vinga-server config apply` for a prompt read of an agent the server is not serving, `vinga-server config device show <mac>` for a code whose device has been bound since, and `vinga-server config <noun> set` for a stored secret written to a holder that is not there. A command is a word of the client's grammar, and the server neither ships that program nor versions it, so an image built before a rename told an operator to type a command the CLI beside it no longer had. The five sentences now state what was refused and stop there, and the body carries `reason`, a closed token from the new `RefusalReason` vocabulary (`code-not-pending`, `agents-unknown`, `agent-not-serving`, `device-already-bound`, `provider-missing`, `mcp-server-missing`), published in `docs/reference/api-openapi.json` as an RFC 9457 extension member. The `vinga` command reads the token and appends the remedy in its own spelling, and prints the server's sentence alone for a token it does not know, so a state added later is quoted rather than guessed at. Every refusal outside those five carries exactly the four members it always has: `reason` is absent from the wire rather than sent as null, so nothing else about this API's refusals changed.

- **Upgrade every administering CLI before the server.** A CLI older than this vocabulary refuses a body carrying a member it does not know, so against a newer server the five refusals above print the unreadable-body sentence rather than what was refused, until the CLI is upgraded. Every other refusal reads as it did, because none of them carries the member. Nothing negotiates a version: the two halves ship from one tree, and the wheel-grade lane tests the installed CLI against a server of the same tree.
