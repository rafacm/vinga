### Changed

- **An unbound device only pairs, on every deployment** (#612). A device with no binding of its own reaches no agent, whether or not `default_agent` is set: with onboarding on it shows and speaks a six-digit activation code, and with `server.onboarding.enabled: false` it gets neither a code nor a token and is bound by its MAC. The devices map is always the allowlist, with no exception for a server on localhost. `default_agent` now means the agent a newly bound device starts with: `vinga device pending claim <code>` takes its agents as optional, and a claim that names none binds the board to the default agent, read inside the claim's own transaction, with the acknowledgement naming the agent it bound; with no default agent set, such a claim is refused and the code stays claimable. `POST /api/devices/pending/{code}` takes a body of its own, `PendingClaim`, whose `agents` may be left out or empty; `PUT /api/devices/{mac}` and `vinga device bind` still require at least one agent. A claim is no longer refused because a default agent was set after the code was issued, and setting a default agent no longer retires the codes boards are showing. The boot no longer requires a default agent when agents are defined and no device is bound: such a deployment is awaiting its first claim. A browser that opens the page with no identity is always minted one and pairs by its code: the mint's two refusals, while a default agent is set and while the bindings cannot be read, are gone. Setting a default agent this server is not serving yet now says it waits for `vinga apply` alone, since it changes no device's check-in, and setting or clearing one that is served says it is read by the next claim. The decision is recorded in `docs/adr/2026-10-07-an-unbound-device-only-pairs.md`.

  Upgrade: boards that reached the default agent without a binding of their own now show an activation code instead of connecting. List them with `vinga device pending list` and claim each with `vinga device pending claim <code>`, which binds it to the default agent it was already reaching; a board bound by MAC is unaffected.
