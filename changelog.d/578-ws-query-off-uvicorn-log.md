### Security

- **A websocket handshake's query string, and any credential in it, is no longer printed by uvicorn** (#578). uvicorn writes one INFO line per websocket handshake, accepted or refused, carrying the client's address and the request path with its query string verbatim, as `127.0.0.1:43106 - "WebSocket /xiaozhi/v1/?...&authorization=Bearer%20<token>" 403`. No client of this server puts anything in that query, since the firmware and the simulator authenticate in a header, but a client built to upstream's convention does, a browser has to, and the refused line printed the token before any of this server's code ran. The logging setup now holds `uvicorn.error` at WARNING where it held it at INFO, so the line is gone at every `server.log_level`, DEBUG included, in both log formats. What is given up is the rest of uvicorn's INFO: the process id at start and finish, `Waiting for application startup.` and `Application startup complete.`, `Uvicorn running on <scheme>://<host>:<port>`, the shutdown notices, and the websockets library's `connection open` and `connection rejected`. A refused handshake is still logged as `auth_rejected` or `session_rejected`, and an accepted one as `session_open` once a valid hello arrives, or `session_rejected` when the session turns the device away first. **An accepted connection that ends before a valid hello is no longer logged at all**: a client that disconnects first, sends no hello within 10 seconds, or sends a first frame that is not text, not a hello, or a hello for another transport, audio format or protocol version is closed without an event, and uvicorn's `connection open` was the only line it left. A first text frame that is not a well-formed protocol message is still logged as a warning. The onboarding banner still names the origin a device reaches (the listen address unless `server.public_url` or `server.websocket_url` names a better one), and the drain still announces the shutdown. Everything uvicorn says at WARNING and above is kept, including a failed bind, a failed startup and an exception in the application with its traceback. There is still no configuration key for these levels.
