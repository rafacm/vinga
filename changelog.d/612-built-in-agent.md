### Added

- **vinga, the built-in agent** (#612). Every deployment now has an agent named vinga that nobody stores: the server composes it from the build it ships in, with a persona of its own followed by the concept summary from the packaged Use pages. It answers about the device it speaks through and about vinga itself, names the commands that do things rather than running them, and hands over to the device's other agents. A device bound to vinga reaches it like any other agent. It is served whenever every provider stage resolves through its own entry or through `agent_defaults`; a stage that resolves nowhere leaves it unserved without refusing the boot. Its memory and its threads are its device's: its `remember` files every fact under the device's scope, with no scope to choose, its memory tools and its prompt reach the device's facts alone, and its search for a conversation to resume finds only the threads held on the device it is talking through, so what it is told on one device is not recalled on another. Every other agent keeps its own agent-scoped memory and threads. Creating an agent named vinga, or renaming one to it, is refused, and a reference refusal's list of defined agents now ends with vinga, the one name a binding or the default agent may always name.

  Upgrade: domain migration `3005_builtin_agent` runs at boot and creates the empty `builtin_agent` table; nothing to do for it. An agent you already have named `vinga` keeps serving exactly as before, its memory and threads with it, and holds the built-in agent back, which `vinga info` and the `builtin_agent_not_served` event say. To bring the built-in agent in, run `vinga agent rename vinga <new>` and then `vinga apply`: the rename moves that agent's bindings, the default agent, its memory and its threads in one transaction. Deleting it instead leaves its remembered facts unread.
- **`builtin_agent`, the built-in agent's overrides** (#612), a new domain key written like `agent_defaults`: `vinga builtin-agent show` and `vinga builtin-agent set`, `GET` and `PUT /api/builtin-agent`, carried by export, import and apply, and shown as pending by `vinga diff` until `vinga apply`. It sets vinga's providers, its voice, its filler, fallback and memory sections, and the shared fragments its prompt carries, which is how its reply language is set. It has no `prompt` and no `mcp` field, so vinga carries no MCP tools, not even those `agent_defaults.mcp` grants every other agent.
- **`builtin_agent_not_served`** (#612), a WARNING event at the boot and at every apply whose world does not serve vinga, with `reason` `displaced` or `unprovided` and, for the second, the provider `stages` it wants. `GET /api/runtime/info` gains `builtin_agent`, read live per request, and `vinga info` prints why vinga is not served and what to run, and nothing while it is served.
