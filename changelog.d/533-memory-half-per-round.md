### Added

- **A reply round now says how big its whole prompt was and which remembered facts were in it** (#533). The `llm_round` event gains `system_characters`, the whole system prompt the round sent; `memory_characters`, what the per-round blocks (the conversation's notes, the agent's remembered facts and the device's block) added to the prompt cached at activation, the blank lines between them included; `memory_sources`, each of those blocks' size by `state`, `memory` and `device`; and `memory_facts`, the ids of the remembered facts the prompt injected, agent block then device block, at most 70. The sizes are present on every reply round whatever the agent's memory setting, since the device block carries the device record too; the id list is present, possibly empty, wherever the round read memory (a read that failed injected nothing and lists nothing) and absent where the agent's memory is off. A reply round that fails after its request was built carries the same four fields on `provider_failed`, which is where a context-length refusal shows up; no recap and no other stage carries them. The `llm` span carries them as `vinga.llm.system.characters`, `vinga.llm.memory.characters`, `vinga.llm.memory.sources.<state|memory|device>` and `vinga.llm.memory.facts`, the ids as integers, with `vinga.llm.memory.fact_count` beside them so a backend can filter on the count. An id joins a trace to the memory store as it is now, best effort: a corrected fact keeps its id with new text and a pruned or deleted one leaves no row. No text of a fact, a note or the prompt reaches any of these fields, and there is no digest of the memory half, since a digest of a short personal fact can be confirmed by hashing guesses.
