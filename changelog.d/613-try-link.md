### Added

- **A try link binds a browser as a device.** `vinga info` prints a new link each time it runs, `<origin>/try/#<token>`, and opening it binds that browser to the default agent before its first word, as a device named `Browser <MAC>` that `vinga list` shows beside the boards. The link works once and expires ten minutes after it was printed, and a restart of the server ends every link not yet opened. It names `server.public_url` when that is an `https://` (or loopback) origin, otherwise `localhost` when `vinga info` reached the API on this machine, and otherwise prints no link and asks for an `https://` `server.public_url`; it never names the listen address. With no default agent set, with onboarding off, or with too many links waiting, `vinga info` prints the reason in the link's place and carries on. The page's conversation client is not built yet, so today opening the link binds the browser and stops there.
- `POST /api/runtime/try-links` issues a try link behind the configuration API's bearer token, answering the page path with the token in its fragment, the origin when the server can name one, and the link's lifetime, under `Cache-Control: no-store`. It refuses with 409, nothing issued, while onboarding is off, while the server serves a configuration no store describes, while no default agent is set (with the new `no-default-agent` refusal reason), and while as many links are waiting as the server holds. `POST /try/redeem` is where the page spends the token: same origin only, one fixed refusal for an unknown, expired, spent or malformed token.

### Security

- The try link's token travels in the URL's fragment, which a browser sends to no server, so opening a link puts the token in no proxy or server access log, and fetching the link (a preview, a prefetch, a scanner) spends nothing. The token is answered by the issuing request alone and printed on the operator's own terminal alone.
- [Exposing a deployment](docs/run/exposing-a-deployment.md) now states as a rule that a reverse proxy must redact or suppress the request target of every `/x/` route before it logs, since each carries the onboarding key, and gives the edge check that proves it; and that it must not log a board's `Authorization` header or a browser's `Sec-WebSocket-Protocol` values, which carry the same device token.
- No route of the server answers with a slash redirect any more. A path with a stray trailing slash used to get a 307 whose `Location` repeated the request's path and query string; every route already answers with and without its trailing slash, and anything else is now an unmatched path.
