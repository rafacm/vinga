### Changed

- **What an agent remembers is read once per conversation, not on every round** (#536). The memory blocks of a reply's system prompt (the conversation's notes, the agent's remembered facts, the device's notes) and the device's name and location used to be read again on every round, so a `remember`, a `forget` or a `set_state` changed the system prompt of the very next round and cost that round the provider's prompt cache entirely. They are now read when an agent starts speaking on a conversation and kept for every later round and reply, so the system prompt stays byte for byte the same and stays cached. What the agent's own memory tools change reaches it as their results, which stay in the conversation since #599, and the memory section now opens with a sentence saying when it was read and that those results are newer than it. It is read again when an agent is handed the conversation (back to the same agent included), when the conversation changes, when the agent's memory setting changes, after a hard deletion, and after a memory write whose answer is longer than the 2 KiB a later reply is sent of a past result; a read that failed is never kept, so the next reply tries again. Where the conversation already holds turns when memory is read again, the fixed note `(memory re-read here)` is placed in the history just before the newest turn, one at a time, and the framing names it as the point memory stands at. The cost is stated rather than hidden: a fact saved by another live session's agent, an operator's correction of a fact, and a device renamed or moved by an operator reach an ongoing conversation at its next conversation rather than its next reply.
- **An agent that may remember is always sent its memory section**, even with nothing saved, where it says `Nothing is saved in memory yet.` after the framing sentence (#536). The heading of the conversation's notes no longer claims they are current: it reads `What this conversation has noted. When anything below disagrees with this, this takes precedence:`. The operator's prompt preview shows the section the same way, and shows none for an agent whose memory is off. `llm_round` and `provider_failed` count the framing in `memory_characters` and in the size of the block it opens, and repeat the same sizes and fact ids on every round that sends the same snapshot.
- **A hard deletion of a remembered fact reaches every live conversation's next reply** (#536). Erasing a fact, or all of an agent's or a board's memory, through `vinga memory delete` and the API behind it, and an agent's own `forget` with `permanently` set, are published to the conversations the server is running once they have removed something, and each reads its memory again before its next reply. A reply already under way may send the fact once more in its remaining rounds. The fact's text in the conversation's own tool exchanges (the `remember` that wrote it, a `recall` that listed it, a `forget` that quoted it) is history rather than memory and keeps being sent, and exported with `export_llm_input` on, while the session lasts; the observability page gives the order that prevents that: end the live session, delete the conversation, then delete the fact.
