### Changed

- **Breaking for trace consumers: the `llm` span no longer carries `langfuse.observation.input` or `langfuse.observation.output`** (#533). With `server.telemetry.export_llm_input` on, the generation span used to carry the assembled request and the model's output twice, under the OpenTelemetry GenAI conventions and again under those two Langfuse fields as copies. It now carries the conventions alone: `gen_ai.system_instructions`, `gen_ai.input.messages` and `gen_ai.output.messages`, with `vinga.llm.tools` and `vinga.llm.tool_choice` beside them, all unchanged. A query, alert, dashboard or Collector rule that reads either Langfuse field on a generation reads `gen_ai.input.messages`, `gen_ai.system_instructions` and `gen_ai.output.messages` instead. There is no deprecation period, deliberately: the copies are what kept the system prompt out of Langfuse (the fix below), and a second spelling of the same content is exactly what this project's rule that every backend reads one set of keys exists to remove. The turn span's transcript and audio fields under the same Langfuse names are unchanged. With the copies gone, what one round may attach holds the input and output once rather than twice, so a request that fit the 256 KiB ceiling still fits, and a long reply is no longer charged twice while it streams.

### Fixed

- **Langfuse now shows a generation's system prompt as the first message of its input** (#533). With `server.telemetry.export_llm_input` on, the system prompt reached the backend under `gen_ai.system_instructions` and Langfuse showed it nowhere, neither in the observation's input nor in its metadata, because it reads its own input field first and the copy written there held the messages without the system prompt. With that copy gone, Langfuse maps the conventions itself and puts the system prompt first, as a `system` turn holding the agent's know-how blocks and the memory blocks that round read. No byte leaves the server that did not before: the system prompt was already on the span, and what changes is that Langfuse now stores and displays it, memory included, which is what `export_llm_input` has described since it shipped.
