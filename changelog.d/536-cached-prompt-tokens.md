### Added

- **A generation now says how much of its prompt the provider served from its cache** (#536). The `llm_round` event gains `cache_read_input_tokens`, on a reply round and on a recap alike, and the `llm` span carries it as the OpenTelemetry GenAI conventions' `gen_ai.usage.cache_read.input_tokens`. It is part of `input_tokens`, never an addition to it. A tracing backend that knows the key takes it out of the input and prices it at the model's cached rate, so a round's cost is what the provider charged rather than an upper bound on it, and a working prompt cache can now be told from none. OpenAI's API reports the count as `prompt_tokens_details.cached_tokens`. A compatible endpoint that sends no such count, or one that cannot be a part of the input it came with (negative, not a whole number, or larger than the input), reports no cached count rather than a zero. The span still carries no second, backend-specific usage spelling for a generation: measured against the backend, one would replace its mapping of the conventions' key rather than add to it. The count is not stored on the turn or in the metrics views.

### Fixed

- **An Anthropic generation's input count now includes the prompt it read from, and wrote to, the provider's cache** (#536). Anthropic reports `input_tokens` net of `cache_read_input_tokens` and `cache_creation_input_tokens`, so the input a round reported was short by both whenever caching was active, while an OpenAI round's input already included its cached prefix. The adapter now folds both into the input count, and reports the read count as the cached share. The server sets no Anthropic cache breakpoint, and caching on that API is opt-in by breakpoint, so nothing moves today. Once an Anthropic entry does cache, the corrected count reaches everything that sums it: the turn's and each leg's `input_tokens`, the API reads of them and the token metrics views. Rows stored before the upgrade are not rewritten, so an Anthropic token series has a step at the upgrade from the day caching becomes active.
