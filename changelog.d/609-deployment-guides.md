### Changed

- **Running a deployment has task guides, one page per task** (#609). A new `docs/run/` directory, indexed one line per guide in `docs/run/README.md` and linked from the Run door of `docs/README.md`, takes the deployment half of the server README: running the container and choosing an image (`running-in-a-container.md`), providing the database (`database.md`), exposing it and the configuration API at the edge (`exposing-a-deployment.md`), limits and the two probes (`limits-and-probes.md`), the master key (`security.md`), upgrading (`upgrading.md`), backups (`backups.md`), recovering a deployment that will not start (`recovering-a-deployment.md`), applying an edit (`configuration.md`) and onboarding a device (`onboarding-a-device.md`). Transports moved to `docs/system-overview.md`. Each guide opens with what you will have at the end and links the generated reference rather than restating it. The server README keeps a `Running in a container` heading that points at the guides, `docs/deployment.md` now defers to them, and the recovery guide asks you to choose between resetting the configuration alone and dropping the whole database before it shows either command. The past releases' upgrade notes are no longer repeated: `upgrading.md` links the changelog entries that carry them. The provisioning command in the guides, in `docs/deployment.md`'s Docker lane, in the recovery recipe of `docs/reference/cli.md` and in the header of `deploy/postgres-init.sql` now takes the admin connection from a libpq service file and `~/.pgpass` (`PGSERVICE=vinga-admin psql -f deploy/postgres-init.sql`) rather than putting a connection URL, password included, in psql's arguments.
