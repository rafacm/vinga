### Changed

- **Configuring and securing a deployment have task guides of their own** (#609). The server README's Configuration, configuration API, Secrets and Security sections, and Applying a change without a restart, move to `docs/run/`: the two halves of the configuration, importing a whole deployment, when an edit takes effect and applying it without a restart (`configuration.md`, retitled Configuring a deployment), the bearer token, the route families, what a write's answer and a refusal carry and how the `vinga` client finds a server (`configuration-api.md`, new), where each credential is kept, the outbound hosts, device authentication, the OTA endpoint, what is exposed and the data boundary (`security.md`), how the server is told where its database is and what it does when it cannot reach it (`database.md`), and which providers what an agent remembers is sent to (`memory.md`). The API's route listings are no longer repeated, since they had drifted from what the server serves; the guide links `docs/reference/api-openapi.json`, which lists every route, body and refusal. The example request no longer expands the API token into curl's arguments: it names a curl configuration file only its owner can read (`curl -K ~/.vinga-api.curl ...`). The `server.local_only` upgrade note is not repeated: `upgrading.md` links the 2026-09-12 changelog entry that carries it. Statements the moved text made that were wrong against the code are corrected, among them: the onboarding key is neither printed at startup nor logged on a wrong attempt; an unknown device with no default agent is shown an activation code unless onboarding is off; the data boundary is checked at every apply as well as at boot; a deployment that never recorded answers the empty shapes rather than a 404; the conversation record also has `/api/metrics`, and live events stream at `/api/runtime/events`; an unset `$VAR` fails the boot only for an entry some agent references; and memory is read when an agent starts speaking in a conversation, not on every reply.
