### Changed

- **An apply whose provider build refuses now says which entry refused, and what about it** (#487). `POST /api/runtime/config/reload`, and the `vinga-server config apply` that calls it, answered a failed provider build with a fixed sentence: the four categories of thing that could have refused, a statement that which one is deliberately not said, and an instruction to start a second server from the same store to find out. The withholding was aimed at a harm this refusal cannot cause. A provider refusal is composed from this repository's own vocabulary: the entry label, and with it whichever that refusal has of an option key, a declared provider type, the rule that was broken or the class of the exception a factory raised, and never the value it refused over. That is exactly why a boot prints the same sentence to stderr as it is. The answer now carries that sentence, behind the prefix every refused reload opens with, so an operator reads what a second server would have told them without starting one. `vinga-server config check` is unchanged and still does not cover this class, because it stops before anything is built; the CLI reference now says which of the two refusals each surface diagnoses. The retained JSON log is unchanged too, and still carries the class of the failure and no exception prose, which is that surface's own contract.

- **The OpenAI text-to-speech provider no longer quotes the configured model when it refuses a steering option** (#487). `model "gpt-4o-mini-tts" ignores option "speed"` becomes `option "speed" is ignored by the model named by option "model"`, and the `instructions` refusal changes the same way. A model name is an option's value, and the rule this surface keeps for every other option it refuses is that the refusal names the key and the rule and never the value. These two were the one place it was broken, which matters on a second surface now that the sentence is what a refused apply answers with.
