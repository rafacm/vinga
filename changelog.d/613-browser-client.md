### Added

- **A browser is now a device you can talk to.** The page a try link opens, at `/try/`, holds a conversation with the default agent the way a board does: press Start, allow the microphone, and speak. It checks in, connects over the same WebSocket, sends Opus at 16 kHz in 60 ms frames and plays the reply. With the browser's echo cancellation on it listens in realtime, so speaking over a reply interrupts it; without it it listens in auto mode and says on the page that speaking cannot interrupt. An Interrupt button stops a reply and an End button ends the conversation; when the server hangs up on a quiet conversation the page says nobody spoke for a while, and Start begins another. A browser holding no identity and no link can paste the onboarding URL instead and pair with a six-digit code, where no default agent is set. The page publishes two device tools, under the firmware's names, that an agent can call: `self.get_device_status` and `self.audio_speaker.set_volume`. Checked in Chromium; a browser that lacks what the page needs (a secure context, AudioWorklet, WebCodecs' Opus) is told what it lacks.
- A browser lane, `tests/browser/`, loads the page from the built wheel's install in headless Chromium and holds four conversations with it on mock providers; CI runs it on every server-workflow event, against the wheel and against the image it built. `docs/contributing.md` has the one command that runs it locally.
