### Changed

- **An agent now keeps its tool exchanges for the rest of the conversation** (#599). Until now the history a later reply was sent held only what the user said and what the agent said aloud, so a fact saved with `remember`, a value changed with `set_state` or anything an MCP or device tool returned was invisible to the agent on its next turn unless it had happened to say it. Every call that has its result is now kept in the thread's history, structured, from the moment it answered, even when the reply it belongs to is then cut short by a barge-in or fails; a call still running when the reply ends, and the move that hands a conversation over, are not. In the reply that made a call the model sees the result whole, as before; on every later reply a result over 2 KiB (2048 UTF-8 bytes, a fixed limit) is replaced by `(result of <tool> cleared: <size> bytes)`, so the model knows to call the tool again if it needs it. A past call to a tool the request no longer offers, because an MCP reload removed it or because the model invented the name, is sent as a plain-text record in the assistant's turn instead: a fixed prefix saying it is quoted data and one JSON object holding the tool, the arguments, the result as kept and the error flag, escaped so nothing a far side answered can end it early. Kept calls carry ids the server minted (`h0`, `h1`, ...) rather than the provider's. A handover still starts the incoming agent clean, and a resumed conversation does not rebuild its exchanges yet. With the LLM input export on, the exported request is the history as sent, cleared notes included. Requests grow by what the kept exchanges add, bounded by the 2 KiB limit per past result.
- **Anthropic requests join consecutive user turns into one message** (#599). A reply that ran a tool and then spoke nothing leaves its tool results last in the history, so the next utterance follows a message that is already the user's; the Anthropic translator now appends the utterance to that message as a text block, and two plain user turns in a row (which a failed reply could already leave) become one message of two text blocks, so the roles alternate as that API requires. OpenAI-compatible requests are unchanged.
