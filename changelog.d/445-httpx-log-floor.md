### Changed

- **The server no longer logs the request line httpx writes for every outbound request** (#445). The logging setup now holds `httpx` and `httpcore` at WARNING where it held them at INFO, so a line such as `HTTP Request: POST https://api.elevenlabs.io/v1/text-to-speech/<voice>/stream?output_format=pcm_24000 "HTTP/1.1 404 Not Found"` no longer reaches the log at any `server.log_level`, DEBUG included. The line carried the full URL, query string and all, composed by the library rather than by this server and outside the closed event vocabulary the rest of the log is held to. Nothing secret was in it with today's providers, which all authenticate in a header, but one that carried a key in its query string would have had it logged verbatim. What is given up is that line for every request, and the HTTP status code a failed call's line carried; a failed provider call is still logged, as `provider_failed`, whose closed fields name the stage, the provider entry with its type and model, the host, the duration and the exception's class name. There is still no configuration key for these levels: a diagnosis that needs the line back raises the logger by name in the process that needs it, after logging is configured.
