## M1: the manifest stops recording positions

PR #475.

### What landed

`vinga-server/tests/unit/test_command_spellings.py` renders the
manifest from the distinct `class  invocation` pairs the census found,
sorted by class and then by invocation, one line each. The rendering is
`manifest_of(rows)`, which takes a census and returns the bytes;
`manifest()` is that over the live census, so the committed artifact
and a synthetic list of `Spelling` rows go through exactly the same
code. Everything else in the module is untouched: the scanner, the
classification rules, the four guards, `Spelling.rendered()` as the
`path:line  class  invocation` diagnostic a failure prints, and the
`__main__` regeneration entry point.

The committed manifest went from 1,706 lines to 451 (442 entries under
a nine-line header). `MANIFEST_HEADER` describes the new shape, says
the file is generated and not to be edited, and names the command that
regenerates it, which the old header left to the module docstring.

Three new cases, in a section of their own at the foot of the module:
one pair quoted in two files renders one line and renders it
independently of scan order; one invocation given two classes renders
two lines; and a site that leaves while a sibling keeps its pair
renders no diff at all.

`AGENTS.md` loses the two sentences the new shape falsifies. The
rebase-traps paragraph said the manifest records line numbers and that
any line shift anywhere restages it; it now says the file moves with
the set of classified spellings, one line per spelling added, removed
or reclassified, and names `test_the_manifest_is_the_census` as what
enforces regenerating rather than merging when it does conflict (the
plan's fourth acceptance box, for the census half). The CI paragraph
said the census is staled by pure documentation moves; it now says a
documentation change can stale it, by a spelling a document starts or
stops quoting or by a move that gives one another class.

### Deviations from the plan

- **The lossy-case test asserts the removal reading, and carries the
  reclassification reading beside it.** The plan's manifest section
  describes the case twice and the two descriptions do not agree: the
  prose says "a site removal or reclassification is invisible when
  another site retains the old pair", while the parenthetical in the
  same paragraph says "two files carrying one pair, one of them moving
  class, manifest unchanged". The second is not true as written: a
  reclassified site adds its new class to the set, so the manifest
  gains a line. The test asserts both halves of what is true, in one
  case: dropping one of two sites of a pair renders byte-identical, and
  reclassifying one leaves the old class standing on the strength of
  the sibling, so the departure is invisible either way.
- **The docstring says `census()` rather than "runs the module" for
  recovering per-site positions.** The plan says a reviewer who wants
  the sites for a pair "runs the module", but the module's `__main__`
  writes the manifest and the manifest is what no longer carries them.
  What is true after this change is that the positions are computed by
  `census()` and printed by every guard failure, and that is what the
  docstring and the manifest header say.
- **The implement-issue skill's census bullet is left alone.**
  `.claude/skills/implement-issue/SKILL.md` also says a documentation
  move can stale the census. It is inside milestone 2's documentation
  footprint, which rewrites that file's changelog bullet, so both edits
  to it land together there rather than half here.

### Discoveries

- **Neither `AGENTS.md` nor the changelog entry moved the manifest.**
  Both documents name the artifact and quote its shape, and neither
  quotes a command spelling the tree did not already have, so the
  regenerated bytes after the documentation edits are the bytes
  regenerated before them. That is the first evidence of the property
  the milestone is for: a documentation change now leaves the artifact
  alone unless the vocabulary itself moved.
- **The falsification mutations are cheap and worth keeping in the
  record.** Keeping duplicates (a list where the set is) fails the
  one-line case and the no-diff case; keying the aggregation on the
  invocation alone fails the two-classes case and the no-diff case.
  Both were run and watched red before the cases were claimed.
- **The changelog entry is dated 2026-09-11 although the session ran
  past midnight**, into the branch's existing `## 2026-09-11` section
  with its siblings. This is the recorded incident the plan's date
  derivation answers: after milestone 2 the section is derived from
  when the change lands on `main`, not from when somebody writes the
  entry.
