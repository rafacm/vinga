Either something the board swap would write is already taken, by a device record answering at the new address or by facts remembered about a board that stood there, or the configuration database's write lock is held by another request. A swap may never merge two records or two memories into one, because nothing afterwards could tell them apart and no second swap could separate them, which is why an occupied destination is refused rather than merged. Nothing was changed and neither address is quoted back. The held lock clears on its own and the request can be made again; an occupied destination does not clear, and what clears it is swapping onto an address nothing is bound to, or taking away what is filed under this one.
